📨 Split Overlay (Outlook-style)

The WYSIWYG email body splits in half during drag — left side attaches the file, right side shares it as a link.

What it is

Outlook online turns the message body into two drop targets the moment you start dragging a file into a draft: drop on the left to attach as a file, drop on the right to share as a OneDrive link. We can build that with what we have today: two <web-dropzone> instances, each with its own overlay-target pointing to one half of a grid container that overlays the editor.

Why it works without new API

The split grid sits invisibly on top of the editor with pointer-events: none. It just carves the editor's rect into a left half and a right half. Each dropzone's overlay independently covers one half — they don't overlap, so they don't fight.

Try it

Drag any file from your desktop onto the message body below. It splits in half — drop on the left to attach as a file, drop on the right to share as a OneDrive-style link.

Stress test: two editors on one page

Same pattern repeated. Each draft has its own pair of dropzones with distinct overlay colors so you can see which is which. Things to verify by dragging:

  • Dragging onto the page lights up all four halves at once (the two pairs are independent stores; the document-level dragenter fires each of their createOverlay paths).
  • Crossing the cursor from Draft A's overlays → through the gap → into Draft B's overlays should not flicker all four out. Each one stays lit until the drag actually ends.
  • Hovering each half should only highlight that one (solid border, brighter fill) and only fire overlay-enter on its host. The other three stay translucent.
  • Dropping on any one of the four should close all four together (the dz:overlay-drag-ended broadcast).
  • Files dropped on Draft A's halves go to Draft A's lists; Draft B's halves to Draft B's lists. No cross-pollination.

How it works

  1. The editor shell is position: relative. Inside it sits the WYSIWYG element and a sibling .split-target grid with position: absolute; inset: 0 — the grid lays exactly over the editor.
  2. The grid is pointer-events: none, so typing into the editor still works while no drag is happening.
  3. The grid has two empty halves. Two <web-dropzone> instances (both display: none) each set overlay-target to one half.
  4. On the first dragenter, each dropzone reads its target's getBoundingClientRect() and renders a fixed-position overlay over that rect. Neither overlay extends past the editor.
  5. Each overlay's background comes from --dz-overlay-bg on its host element, so the two halves can look visually distinct.
  6. Picked files render in <web-dropzone-list> satellites placed in the attachments row beneath the editor.
  7. Each overlay fires overlay-enter / overlay-leave on its host as the cursor crosses in / out during the drag — useful for surfacing remaining-quota text or other contextual info. Detail: { files, overlayElement }. The hovered overlay also gets a solid border, brighter fill, and a dz__overlay--hover class hook.
<div class="editor-shell" style="position:relative">
  <div contenteditable="true" class="wysiwyg">...message body...</div>

  <!-- Invisible grid overlaying the editor -->
  <div style="position:absolute; inset:0; display:grid;
              grid-template-columns:1fr 1fr; pointer-events:none">
    <div id="left-half"></div>
    <div id="right-half"></div>
  </div>
</div>

<!-- Hidden dropzones, each targeting one half -->
<web-dropzone style="display:none; --dz-overlay-bg: rgba(0,120,212,0.92)"
              overlay-target="left-half"
              overlay-text="Attach as file"
              overlay-icon="📎"></web-dropzone>

<web-dropzone style="display:none; --dz-overlay-bg: rgba(20,184,166,0.92)"
              overlay-target="right-half"
              overlay-text="Share as OneDrive link"
              overlay-icon="☁️"></web-dropzone>
