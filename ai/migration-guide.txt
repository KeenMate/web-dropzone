MIGRATION GUIDE
===============

CRITICAL: Guide for migrating from other multiselect libraries
- From Select2
- From Choices.js
- From Tom Select
- From React Select
- From Vue Multiselect
- Common pitfalls and solutions

FROM SELECT2
------------
jQuery-based → Web Component

Select2 (jQuery):
$('#mySelect').select2({
  placeholder: 'Select options',
  allowClear: true,
  data: options
});

Web Multiselect:
<web-multiselect
  search-placeholder="Select options">
</web-multiselect>

<script>
  const select = document.querySelector('web-multiselect');
  select.options = options;
</script>

Key differences:
- No jQuery dependency
- Web Component (works everywhere)
- Native shadow DOM
- Better performance

Migration steps:
1. Remove jQuery and Select2
2. Import web-multiselect
3. Replace <select> with <web-multiselect>
4. Update initialization code
5. Update event handlers

Events mapping:
Select2 → Web Multiselect
select2:select → 'select'
select2:unselect → 'deselect'
select2:change → 'change'
select2:open → (no direct equivalent)
select2:close → (no direct equivalent)

FROM CHOICES.JS
---------------
Vanilla JS library → Web Component

Choices.js:
const choices = new Choices('#mySelect', {
  removeItemButton: true,
  searchEnabled: true,
  placeholderValue: 'Select options'
});

Web Multiselect:
<web-multiselect
  search-placeholder="Select options">
</web-multiselect>

<script>
  const select = document.querySelector('web-multiselect');
  select.options = options;
</script>

Key differences:
- Web Component vs library instance
- No manual instantiation needed
- Built-in badge removal
- Better virtual scrolling

Migration steps:
1. Remove Choices.js
2. Import web-multiselect
3. Replace element
4. Update configuration
5. Update API calls

API mapping:
Choices → Web Multiselect
setChoices() → options property
getValue() → getValue()
setValue() → setSelected()
clearStore() → setSelected([])
destroy() → destroy()

FROM TOM SELECT
---------------
Modern vanilla library → Web Component

Tom Select:
new TomSelect('#select', {
  create: true,
  sortField: 'text',
  maxItems: 5
});

Web Multiselect:
<web-multiselect allow-add-new="true">
</web-multiselect>

<script>
  const select = document.querySelector('web-multiselect');
  select.options = sortedOptions;

  select.addNewCallback = (value) => ({
    value: value,
    label: value
  });
</script>

Key differences:
- Declarative vs imperative
- Web Component standard
- No plugin system needed
- Built-in virtual scrolling

FROM REACT SELECT
-----------------
React component → Web Component

React Select:
import Select from 'react-select';

<Select
  options={options}
  isMulti
  onChange={handleChange}
/>

With Web Multiselect:
import '@keenmate/web-multiselect';
import { useRef, useEffect } from 'react';

function MyComponent() {
  const selectRef = useRef(null);

  useEffect(() => {
    const select = selectRef.current;
    if (!select) return;

    select.options = options;

    const handleChange = (e) => {
      console.log(e.detail.selectedOptions);
    };

    select.addEventListener('change', handleChange);
    return () => select.removeEventListener('change', handleChange);
  }, [options]);

  return <web-multiselect ref={selectRef} />;
}

Key differences:
- Not React-specific
- Works in all frameworks
- Native browser component
- No React overhead

FROM VUE MULTISELECT
--------------------
Vue component → Web Component

Vue Multiselect:
<template>
  <multiselect
    v-model="selected"
    :options="options"
    :multiple="true">
  </multiselect>
</template>

With Web Multiselect:
<template>
  <web-multiselect
    ref="select"
    @change="handleChange">
  </web-multiselect>
</template>

<script setup>
import '@keenmate/web-multiselect';
import { ref, onMounted } from 'vue';

const select = ref(null);
const selected = ref([]);

onMounted(() => {
  select.value.options = options;
});

const handleChange = (e) => {
  selected.value = e.detail.selectedOptions;
};
</script>

Key differences:
- Not Vue-specific
- No v-model (use events)
- Works without Vue
- Framework-agnostic

COMMON MIGRATION PATTERNS
--------------------------
Setting options:

Old (various):
$('#select').select2({data: options});
choices.setChoices(options);
tomSelect.addOptions(options);

New:
select.options = options;

Getting selection:

Old (various):
$('#select').val();
choices.getValue();
tomSelect.getValue();

New:
select.getValue();

Clearing selection:

Old (various):
$('#select').val(null).trigger('change');
choices.clearStore();
tomSelect.clear();

New:
select.setSelected([]);

CONFIGURATION MAPPING
---------------------
Common config across libraries:

Placeholder:
placeholder → search-placeholder

Multiple selection:
multiple: true → multiple="true"

Search:
searchEnabled: true → enable-search="true"
allowClear: true → (built-in with badge X buttons)

Max items:
maxItems: 5 → (implement in changeCallback)

Create/add new:
create: true → allow-add-new="true"

Loading:
ajax: {...} → searchCallback

Sorting:
sortField: 'text' → (sort options array before setting)

DATA FORMAT DIFFERENCES
-----------------------
Most libraries use similar formats:

Old (generic):
{id: 1, text: 'Option 1'}
{value: 1, label: 'Option 1'}

Web Multiselect (default):
{value: 1, label: 'Option 1'}

Or use callbacks:
select.getValueCallback = (item) => item.id;
select.getDisplayValueCallback = (item) => item.text;

EVENT HANDLING MIGRATION
------------------------
Old (jQuery-style):
$('#select').on('select2:select', function(e) {
  console.log(e.params.data);
});

New (standard DOM):
select.addEventListener('select', (e) => {
  console.log(e.detail.option);
});

Old (library instance):
choices.passedElement.element.addEventListener('change', handler);

New:
select.addEventListener('change', handler);

STYLING MIGRATION
-----------------
Most libraries use CSS classes:

Old:
.select2-container {...}
.choices {...}

New (CSS variables):
web-multiselect {
  --ml-accent-color: #3b82f6;
  --ml-border-radius: 0.5rem;
}

Or inject styles:
select.customStylesCallback = () => {
  return `.option { ... }`;
};

AJAX/ASYNC SEARCH
-----------------
Old (Select2):
$('#select').select2({
  ajax: {
    url: '/api/search',
    processResults: function(data) {
      return {results: data};
    }
  }
});

New:
select.searchCallback = async (searchTerm) => {
  const response = await fetch(`/api/search?q=${searchTerm}`);
  return await response.json();
};

TEMPLATES/CUSTOM RENDERING
--------------------------
Old (Select2):
$('#select').select2({
  templateResult: function(item) {
    return $(`<span>${item.text}</span>`);
  }
});

New:
select.renderOptionContentCallback = (option) => {
  return `<span>${option.label}</span>`;
};

PLUGINS/EXTENSIONS
------------------
Some libraries have plugin systems:

If you need features:
1. Check if built-in (likely is)
2. Use callbacks for customization
3. Use customStylesCallback for styling
4. Use action buttons for bulk operations

Most "plugins" are unnecessary with web-multiselect

PERFORMANCE COMPARISON
----------------------
Typical benchmarks (10,000 items):

Select2: ~2000ms load, laggy scroll
Choices.js: ~800ms load, smooth scroll
Tom Select: ~500ms load, smooth scroll
React Select: ~400ms load (in React)
Web Multiselect: ~30ms load (virtual scroll), 60fps scroll

Virtual scrolling is automatic at 100+ items

BUNDLE SIZE COMPARISON
----------------------
Approximate sizes (minified + gzipped):

Select2: ~30KB + jQuery (~30KB) = 60KB
Choices.js: ~20KB
Tom Select: ~25KB
React Select: ~30KB + React (~40KB) = 70KB
Vue Multiselect: ~15KB + Vue (~30KB) = 45KB
Web Multiselect: ~35KB (standalone)

No framework dependencies needed

COMMON PITFALLS
---------------
❌ Forgetting to import
Fix: import '@keenmate/web-multiselect';

❌ Using jQuery patterns
Fix: Use standard DOM methods

❌ Expecting immediate DOM availability
Fix: Use customElements.whenDefined()

❌ Using .val() instead of .getValue()
Fix: Use Web Component API

❌ Setting options via attribute
Fix: Use property: select.options = [...]

❌ Styling Shadow DOM with external CSS
Fix: Use CSS variables

❌ Expecting v-model to work
Fix: Use change event + setSelected()
