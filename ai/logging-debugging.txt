LOGGING & DEBUGGING
===================

CRITICAL: Categorized logging system for debugging
- 4 categories: INIT, DATA, UI, INTERACTION
- Runtime enable/disable
- Log level control (error, warn, info, debug, trace)
- Color-coded console output
- No performance impact when disabled

ENABLING LOGGING
----------------
Enable all logging:

import { enableLogging } from '@keenmate/web-multiselect';
enableLogging();

Or via global API:
window.components['web-multiselect'].logging.enableLogging();

DISABLING LOGGING
-----------------
Disable all logging:

import { disableLogging } from '@keenmate/web-multiselect';
disableLogging();

Or:
window.components['web-multiselect'].logging.disableLogging();

LOG CATEGORIES
--------------
Four logging categories:

MULTISELECT:INIT
- Component initialization
- Configuration setup
- DOM mounting
- Shadow DOM creation

MULTISELECT:DATA
- Option processing
- Data transformation
- Selection changes
- Value updates

MULTISELECT:UI
- Rendering
- Dropdown positioning
- Virtual scrolling
- UI updates

MULTISELECT:INTERACTION
- User interactions
- Keyboard events
- Mouse events
- Search operations

LOG LEVELS
----------
Five log levels (lowest to highest):

trace: Verbose debugging
- Every function call
- Internal state changes
- Performance markers

debug: Detailed debugging
- Key operations
- Decision points
- Data structures

info: General information
- Important events
- State transitions
- User actions

warn: Warnings
- Non-critical issues
- Deprecations
- Best practice violations

error: Errors
- Critical failures
- Exceptions
- Invalid states

SETTING LOG LEVEL
-----------------
Global log level:

import { setLogLevel } from '@keenmate/web-multiselect';
setLogLevel('debug');

Levels: 'error', 'warn', 'info', 'debug', 'trace'

Or via global API:
window.components['web-multiselect'].logging.setLogLevel('debug');

CATEGORY-SPECIFIC LEVELS
------------------------
Set level for specific category:

import { setCategoryLevel } from '@keenmate/web-multiselect';

setCategoryLevel('MULTISELECT:DATA', 'debug');
setCategoryLevel('MULTISELECT:UI', 'warn');
setCategoryLevel('MULTISELECT:INIT', 'info');
setCategoryLevel('MULTISELECT:INTERACTION', 'debug');

This allows fine-grained control

PRODUCTION BUILDS
-----------------
Disable logging in production:

// main.js
if (import.meta.env.PROD) {
  import { disableLogging } from '@keenmate/web-multiselect';
  disableLogging();
}

Or check NODE_ENV:
if (process.env.NODE_ENV === 'production') {
  disableLogging();
}

PERFORMANCE IMPACT
------------------
When disabled: Zero overhead
- No log statements executed
- No string formatting
- No console calls

When enabled:
- Minimal impact
- Only active categories log
- Console.log is async

-------------------
Log callback execution:

select.searchCallback = async (searchTerm) => {

PERFORMANCE PROFILING
---------------------
Measure performance:

console.time('options-update');
select.options = largeArray;
console.timeEnd('options-update');

console.time('dropdown-open');
// Click to open dropdown
console.timeEnd('dropdown-open');

Or use Performance API:
const start = performance.now();
select.options = largeArray;
const end = performance.now();
console.log(`Update took ${end - start}ms`);

MEMORY DEBUGGING
----------------
Check memory usage:

// Before
const before = performance.memory?.usedJSHeapSize;

// Create multiselect
const select = document.createElement('web-multiselect');
select.options = largeArray;
document.body.appendChild(select);

// After
const after = performance.memory?.usedJSHeapSize;
console.log(`Memory increase: ${(after - before) / 1024 / 1024}MB`);

NETWORK DEBUGGING
-----------------
Debug async search:

select.searchCallback = async (searchTerm) => {
  console.log('Fetching results for:', searchTerm);

  const start = performance.now();
  const response = await fetch(`/api/search?q=${searchTerm}`);
  const end = performance.now();

  console.log(`Fetch took ${end - start}ms`);

  const results = await response.json();
  console.log(`Returned ${results.length} results`);

  return results;
};

ERROR HANDLING
--------------
Log errors:

select.searchCallback = async (searchTerm) => {
  try {
    const response = await fetch(`/api/search?q=${searchTerm}`);
    return await response.json();
  } catch (error) {
    console.error('Search failed:', error);
    return [];
  }
};

Catch render errors:
select.renderOptionContentCallback = (option, context) => {
  try {
    return customRender(option, context);
  } catch (error) {
    console.error('Render error:', error);
    return option.label;  // Fallback
  }
};
