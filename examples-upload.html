📤 Simulated Uploads

Fake-upload pipelines wired via the public JS API — see progress bars, completion, and error states.

How this page works

web-dropzone's built-in upload pipeline takes a single async handler. The component runs files through a worker pool of size concurrency, awaits each handler Promise, drives file.status from the outcome, and exposes Pause / Resume / Cancel / Retry. The handler signature includes a context arg carrying resume offset and persistent metadata — so handlers backed by Content-Range / tus.io / S3 multipart can pick up where a paused upload left off:

dropzone.uploadFileCallback = async (file, onProgress, signal, context) => {
    // file       — the native File blob
    // onProgress — call with 0..100 to tick the progress bar
    // signal     — AbortSignal fires on pause / cancel / remove
    // context    — { startBytes, startPercent, metadata, setMetadata(patch) }
    //              startBytes > 0 means "resume from here"
    //              context.metadata carries state stashed in prior attempts
    //              setMetadata(patch) saves state for the NEXT attempt
}
dropzone.concurrency = 3        // max 3 in flight (default 1)
dropzone.autoUpload   = true    // start uploads on add (default)

Status badges, the per-file progress column inside the popover, and the overall progress strip (with Pause all / Resume all / Retry all buttons) all wire themselves up automatically. The plain list / detailed appearances don't show per-file progress — use one of the rich appearances for upload UI.

For apps with a bespoke upload manager, the older fire-and-forget escape hatch (file-added event + updateFileProgress / setFileStatus) still works — just leave uploadFileCallback unset.

Playground

One dropzone, all the knobs — selector + list appearance, success rate, concurrency, per-file duration, auto vs. manual upload. Every control persists to localStorage under the dz-upload- prefix so your last setup survives a reload. Manual mode lets you stage files and click Start uploads when ready — useful for "stage everything, submit on form submit" patterns.

The handler is resume-aware — it honors context.startBytes and stashes an attempt counter in file.metadata via context.setMetadata. Pause + Resume continues from where the bar stopped; per-row Retry (or "Retry all") restarts a failed upload from 0. The log panel below distinguishes fresh starts, resumes (mid-stream after pause), and retries (fresh start after a failure) so you can verify the metadata flows correctly across each transition. Drop the success rate to ~30% and you'll see the failure → retry loop in action.

How to wire a real upload

Set uploadFileCallback to a function that does the actual fetch() against your endpoint. The component handles the rest — queue, concurrency, status transitions, abort signal for pause/cancel/remove.

Single-shot upload (server-side state not resumable):

dropzone.uploadFileCallback = (file, onProgress, signal, ctx) => new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest()
    xhr.upload.addEventListener('progress', (ev) => {
        if (ev.lengthComputable) onProgress((ev.loaded / ev.total) * 100)
    })
    xhr.onload  = () => xhr.status < 400 ? resolve() : reject(new Error(xhr.statusText))
    xhr.onerror = () => reject(new Error('Network error'))

    // Pause / cancel / remove all abort via this signal. Cancel the XHR so
    // the upstream request is also dropped.
    signal.addEventListener('abort', () => {
        xhr.abort()
        reject(new DOMException('Aborted', 'AbortError'))
    })

    const formData = new FormData()
    formData.append('file', file, file.name)
    xhr.open('POST', '/api/upload')
    xhr.send(formData)
})

Resume-aware upload (tus.io / HTTP Content-Range pattern):

dropzone.uploadFileCallback = async (file, onProgress, signal, ctx) => {
    // 1. Get / create the server-side session URL. On resume, ctx.metadata
    //    carries the URL we stashed during the first attempt.
    let uploadUrl = ctx.metadata?.uploadUrl
    if (!uploadUrl) {
        const init = await fetch('/api/uploads', {
            method: 'POST',
            headers: { 'Upload-Length': String(file.size) }
        })
        uploadUrl = init.headers.get('Location')
        ctx.setMetadata({ uploadUrl })  // ← persists across pause / resume
    }

    // 2. Confirm the server's current offset (tus.io HEAD), or trust
    //    ctx.startBytes if you maintain offset client-side.
    const head = await fetch(uploadUrl, { method: 'HEAD' })
    const offset = parseInt(head.headers.get('Upload-Offset') ?? '0', 10)

    // 3. PATCH from offset to end. file.slice() returns a Blob.
    const slice = file.slice(offset)
    const res = await fetch(uploadUrl, {
        method: 'PATCH',
        headers: {
            'Upload-Offset': String(offset),
            'Content-Type': 'application/offset+octet-stream'
        },
        body: slice,
        signal  // abort propagates here
    })
    if (!res.ok) throw new Error(`Upload failed: ${res.statusText}`)

    // 4. Optional — return server-assigned id / download URL for file-deleted.
    return {
        metadata: { ...ctx.metadata, serverGuid: res.headers.get('X-File-Id') },
        downloadUrl: res.headers.get('X-Download-Url')
    }
}

// Optional knobs
dropzone.concurrency = 3
dropzone.autoUpload  = true
dropzone.retryPolicy = { attempts: 3, delayMs: 1000, backoff: 2 }
